# 모듈러 집계 + 비공개 검증 후보: ASR/AMR 수치·누출 감사

2026-10-06 후속 방향은 [ASR·비공개 MGF 설계 계약](../asr-modular-private-mgf-design.md)을
따른다. 아래 AMR 검토와 직접 norm 기본 후보는 당시의 감사 이력이다. 현재 설계는
ASR과 원본 masked-MGF 검사식을 유지하며, 이 문서의 수치 결과를 새 ZKP 구현이나
새 HPRF의 보안성 검증으로 해석하지 않는다.

상태: **설계 후보와 공개 fixture 감사. ZKP·Flower 연결·보안 AMR은 미구현.**
기존 런타임을 AMR로 전환하지 않았다. 실제 학습·네트워크 공격 시험도 아니다.
원본 artifact의 수치 재현과 안전한 새 프로토콜 설계는 별도 작업이다.

이번 결론은 “AMR로 바꾸면 해결”이 아니다. 현재 source VSS와 HPRF의 모듈러스가
다르고, 원본 scalar HPRF는 공개 출력에서도 키를 역산할 수 있다. 따라서
**합계 키 차분 정책과 HPRF 자체를 먼저 해결해야 한다.** ZKP는 잘못된 primitive를
안전하게 만들지 않는다. 아래 성공 결과도 비공개성의 증거가 아니다.

## 1. 검증 대상과 프로필 구분

새 후보의 공통 집계 wire는 다음과 같다. 벡터 식은 좌표마다 적용한다.

```text
z_i = round(S * x_i)
h_i = H(k_i, task/round/block)
C_i = (Delta * z_i + h_i) mod p
```

클라이언트는 `C_i`와 증명만 전송한다. `z_i`, `h_i`, 실수형 검사 벡터를 공개하지
않는다. 증명의 공개 입력에는 최초 key commitment, task/client/round/block,
이전 모델 digest, codec·bound·검사 프로필을 고정한다. 원본 artifact의 입력은
실제로 `round+block`이므로, task 구분까지 포함한 안전한 입력 설계가 구현됐다는
뜻은 아니다. 다른 bound로 같은 입력에 반복 질의해 norm을 탐색하게 해서도 안 된다.

- **새 설계 기본 후보:** `sum_j z_ij^2 <= (B_r*S)^2`를 직접 증명한다.
  실수 마스크 `alpha_r*h_i`는 검사식에서 제거한다. 다만 `C_i`의 마스크가 실제
  HPRF 출력이라는 증명은 여전히 필요하다.
- **MGF 비교 후보:** 비공개 witness `v_i=z_i/S+alpha_r*h_i`에 대해 원본의
  masked-norm 조건을 증명한다. 원본 MGF와의 비교 실험용이며 직접 norm 제한과
  동일한 필터가 아니다. 원본 float와 양자화된 `z_i/S`의 차이도 기록해야 한다.

직접 norm 제한은 실제 입력의 상한을 명확히 한다. 하지만 두 통과 집합은 일반적으로
포함 관계가 아니다. 마스크가 음수 업데이트를 상쇄할 수도 있으므로 “모든 입력에서
원본보다 엄격하다”라고 쓰지 않는다. norm 제한 자체가 올바른 SGD나 모든 poisoning의
부재를 증명하지도 않는다. classifier 일부만 검사하면 전체 업데이트 bound가 아니다.

초기 `B_1`은 공개 설정으로 정한다. 후속 공개 집계에서 bound를 갱신하는 것도 가능하나
`||sum z_i||/|A|`는 개별 norm의 percentile이 아니다. 상쇄 때문에 0일 수도 있다.
최솟값·최댓값·갱신 규칙을 사전 고정하고 학습 성능을 별도로 검증해야 한다.
공개 고정 bound가 있다는 것만으로 DP를 제공하지는 않는다.

이 새 기본 후보는 **원본 Aion-MGF 그대로의 포팅이 아닌 변경 설계**다. 기존 원본
재현 경로를 조용히 대체하거나, 그 실험 결과와 한 묶음으로 보고하지 않는다.

## 2. 복원식과 용량 조건

ASR에서 합계 키 `K_A=sum k_i`가 올바르게 복원됐다고 가정하면:

```text
sum h_i = H(K_A, r) + c*p + e
R = center_p((sum C_i - H(K_A, r)) mod p)
  = Delta * sum z_i + e
recovered_sum = round(R / Delta) / S
```

마지막 두 줄에는 아래 충분조건이 필요하다. `N_max`는 최대 선택 인원,
`B_z`는 **모든 좌표의** 공개 정수 상한, `E`는 해당 복원 경로의 최악 오차 상한이다.

```text
|z_ij| <= B_z
Delta > 2*E
p > 2*(Delta * N_max * B_z + E)
```

원본 round-to-nearest 산술의 ASR 대조군에는 보수적으로 `E=(N_max+1)/2`를 썼다.
`Delta=2*N_max+2`는 이를 만족한다. AMR에는 이 E를 재사용하면 안 된다.
조건을 만족하면 임의의 mask carry `c*p`는 모듈러 뺄셈에서 없어지고 작은 `e`만
남는다. 개별 마스크 합 자체가 p 미만이어야 하는 것은 아니다.

실수 좌표를 먼저 `|x_ij|<=B_x`로 제한한다면 `B_z=ceil(S*B_x+1/2)` 같은 보수적
설정을 쓸 수 있다. 양자화 **이후**의 정수 norm을 증명하는지, 원래 실수 norm을
증명하는지 구분한다. 실수에서 정수로 반올림할 때 L2 오차는 최대 `sqrt(d)/(2S)`다.
가중 집계라면 가중치를 포함한 정수 범위와 전체 기여량으로 용량을 다시 계산한다.

따라서 `S`, `N_max`, `B_z`, `Delta`, HPRF의 출력 p는 함께 선택한다.
p를 늘리면 LWR 압축·보안 조건과 내부 q·차원도 재검토해야 한다. “q도 같은 비율로
키우면 보안이 유지된다”는 결론은 아니다. 출력은 모듈러 링이면 되고, 실제 source
비밀분산 필드와 자동으로 같은 공간이 되지는 않는다.

토이의 `p=101, Delta=8, S=10, N_max=2, B_z=3, E=1`은
`8>2`, `101>2*(8*2*3+1)=98`을 만족한다. 실제 합 `Delta*(2+3)=40`도 중심 범위 안이다.

## 3. 마스크 바인딩이 없을 때의 위조

```text
정상: z=(2,3), h=(80,70), H(K)=49, p=101, Delta=8, S=10
C=(96,94)
(96+94-49) mod 101 = 40 -> 정수 합 5 -> 실수 합 0.5

위조: z_1=2는 그대로 증명하지만 h'_1=80+8=88이라고 주장
C'_1=(8*2+88) mod 101 = 3
(3+94-49) mod 101 = 48 -> 정수 합 6 -> 실수 합 0.6
```

초기 key/share와 증명하는 `z_1`은 바뀌지 않는다. 위조는 Delta의 정확한 배수라
padding/반올림 검사도 잡지 못한다. 그러므로 적어도 다음 관계가 함께 묶여야 한다.

1. 증명의 k가 최초 검증된 비밀분산 commitment의 k와 같다.
2. h는 그 k와 승인된 입력으로 계산한 정확한 HPRF 출력이다.
3. C는 그 h와 norm을 증명한 z로 생성됐다.
4. z의 signed 표현·좌표 범위·norm 조건이 올바르다.

이는 이 후보에서 사용하는 충분한 바인딩 방식이다. 모든 가능한 secure aggregation이
개별 PRF 회로 증명을 반드시 요구한다는 보편적인 하한 주장은 아니다. 동등한 집계
일치성 프로토콜을 쓰려면 그 프로토콜의 별도 안전성 논증이 필요하다.

현재 source 클라이언트 상태가 이 증명에 필요한 Pedersen opening witness까지 보존하고
연결하는 것은 확인·구현해야 할 일이다. 서명이나 payload hash만으로 위 관계가 증명되지 않는다.

## 4. ZKP 비용과 잔차 L2 압축의 경계

[BLMR §5](https://crypto.stanford.edu/~klewi/papers/homprf-proc.pdf)의 공개 행렬 곱은
공개 입력별로 미리 계산할 수 있다. 서로 다른 block 입력도 구분해야 한다. 따라서
증명 안에서 매번 행렬-행렬 곱을 해야 한다는 전제는 잘못이다. 남는 관계는 예를 들어:

```text
<a_j,k> = t_j + q*w_j                  (정수 등식)
0 <= t_j < q
q*h_raw_j <= p*t_j + floor(q/2) < q*(h_raw_j+1)
h_j = h_raw_j mod p
```

원본 구현은 raw 출력 p를 허용하므로 이를 0으로 매핑하는 경우도 처리한다.
위 부등식은 반올림 tie까지 지정한다. 단순 `|q*h-p*t|<=q/2`만으로 tie 규칙을
모두 지정했다고 보지 않는다. proof-native 필드에서의 등식만 확인하면 별도 모듈러
wrap이 가능하므로 k/t/w/잔차의 정수 표현과 범위를 통제해야 한다. 정확한 정수 등식과
다른 범위에서 w의 범위가 이미 따라온다면 별도 w range proof는 중복일 수 있다.

공개 행렬 곱의 전처리는 유용하지만, 공개-비밀 내적 전체와 범위증명은 공짜가 아니다.
벡터 key 폭을 m, 출력 차원을 d라 하면 일반적인 dense 연산량은 `O(d*m)`이다.
선형 관계 batching도 witness commitment 이후의 challenge와 soundness 분석이 필요하다.
Bulletproofs 등의 구체 회로·정수 limb 설계·보안 파라미터를 정하지 않은 상태에서
“10^8 제약이라 불가능” 또는 “100K 차원에서 수십 초” 어느 쪽도 측정 결과로 쓰지 않는다.
**공개 전처리로 줄일 수 있는 부분과 전체 차원 범위검사 비용이 남는다는 것만 확인했다.**

잔차 L2 상한으로 좌표별 정확한 반올림을 대체하는 안도 아직 채택하지 않는다.
`sqrt(d)*q/sqrt(12)`는 분포를 가정한 전형적 크기이지 최악 상한이 아니다.
좌표 수 d와 참여자 수 N을 혼동하면 안 된다. 한 클라이언트의 Delta 크기 변조만
배제해도 여러 악성 클라이언트의 작은 변조가 합쳐지는 경우는 남는다.

`relaxed_l2_counterexample()`은 원본 HPRF와 적법한 비영(nonzero) scalar 키
`1+((7919*i+31336) mod 100000)`을 사용해 이 차이를 수치 검증한다:

- `d=100000, N=100, Delta=202, r=4`, 모든 z=0. k/t/w와 진짜 마스크는 원본식으로 계산한다.
- 악성 20명이 같은 좌표의 h에 각각 10을 더한다. 변경된 h도 출력 범위 안이다.
  20명 모두 제안된 L2 조건에 통과하고, 최대 `잔차 norm^2 / (d*q^2/12)`는
  `488673/625000 = 0.7818768`이다. k/t/w는 전혀 바꾸지 않는다.
- 정확한 좌표별 반올림 조건이라면 이 20명 모두 거부된다.
- 정상 집계는 0이지만 변조 후 그 좌표의 복원 잔여값은 200이므로
  `round(200/202)=1`. 증명하려는 z의 합은 여전히 0이다.

이것은 **완화된 잔차 predicate**의 반례이며, 실제 ZKP나 Flower 공격을 실행한 것이
아니다. 정확한 HPRF 증명을 깨는 공격도 아니다. 이 완화를 쓰려면 더 커진 개별·합계
오차를 Delta/용량에 반영하고 새 soundness 주장을 해야 한다. 기존 작은 E의 증명을
그대로 쓸 수 없다.

## 5. 우선순위 1: ASR의 다중 집합 합계 키 공개

```text
K_{1,2,3,4} - K_{1,2,3} = k_4  (키 합산 공간에서)
```

두 키 합을 볼 수 있는 집계자에게 성립한다. 네트워크 도청자에게 모든 값이 평문으로
방송돼야 하는 공격이 아니다. 선택 명단 서명·BFT·share 암호화가 있어도 정당하게
복원된 두 합을 같은 집계자가 알 수 있다면 차분할 수 있다.

따라서 **한 번 탈락하면 영구 배제하는 정책도 해결책이 아니다.** 복귀하지 않아도
최초 제거 때 차분이 생긴다. 노출된 키가 같은 epoch에 계속 사용됐다면 저장해 둔
해당 클라이언트의 masked update에서 과거 마스크를 제거할 수 있고, 재사용되는
향후 메시지도 위험하다. 키가 이미 독립적으로 갱신된 다른 epoch까지 복원된다는 뜻은 아니다.

단, 모든 roster 변경이 곧바로 개인 키 하나를 노출하는 것은 아니다. 차이가 한 명이거나,
다른 차이 참여자의 키를 알고 있거나, 누적 합계의 연립방정식이 개인 키를 식별할 때
발생한다. 최소 선택 인원 2명 제한만으로는 충분하지 않다.

[Aion §4.3–4.4](https://www.usenix.org/system/files/usenixsecurity25-liu-yizhong.pdf#page=9)는
다중 라운드 합계 키 문제와 CCS, 대안 AMR을 설명한다. CCS만 붙여 이후 MGF/dropout이
만드는 부분집합까지 자동으로 안전해진다고 취급하지 않는다. 적법한 필터링과 공정한
참여 선택도 누적 키 합의 선형 정보를 없애지 못한다.

대안의 현재 판정:

- 독립 fresh key/재분산: 라운드 간 같은 키 합 차분을 없애지만 일회성 분산 목표를 잃는다.
  **원본 HPRF의 역산 취약점은 키 갱신만으로 해결되지 않는다.**
- 고정 cohort, 변경 시 전체 중단/새 epoch: 공개 부분집합을 제한할 수 있으나 동적 필터링과
  다른 기능이다. 합계만 남은 정직한 한 명을 드러내는 등 collusion 조건도 검토해야 한다.
- AMR/threshold mask evaluation: 일회성 공유를 유지할 잠재적 방향이지만, 아래의 정확성,
  primitive 보안성, 동일 입력에 대한 다중 부분집합 질의 방지를 함께 해결해야 한다.

특히 안전한 HPRF라도 **같은 round/input**에 상이한 mask 합들을 공개해 singleton을
고립시키면 해당 라운드 마스크가 노출될 수 있다. 인증된 round별 유일한 release 정책이
필요하다. AMR이라는 이름만으로 모든 선택 질의가 허용되는 것은 아니다.

## 6. 요청한 288좌표 AMR + Delta 실험

고정된 공개 fixture만 사용했다. `N=2,20,100`, `r=1,4,60`, 각 32좌표로 **변형당
288좌표**다. `B_z=1000000`, `Delta=2*N+2`는 결과를 보기 전에 정했다.
2-share 복원을 사용하며 합계 polynomial 계수는 deterministic SHAKE로 만들고
라운드 간 재사용한다. 이는 분산 산술 fixture이며 VSS 메시지·Pedersen 검증을 실행하지 않는다.

읽은 artifact의 실제 파라미터:

```text
p = 14760426300877770769
q = 73802131504388853845 = 5*p
source VSS ORDER: 2047 bits, ORDER mod q != 0
matrix SHA256: 32076498cd7767ddbd73d3cfeb8ea59d0f0e26daa116d235fe48aefdb5f4c512
initialization_values SHA256: 97d73d8377139320a8444f8931e17ddceffb4169f62f07805d108d0825808a18
```

이는 `init.py`의 설정 예시가 아니라 로드한 파일의 값이다.

| 복원 방식 | share 인덱스 | 정확 복원 좌표 | 최대 관측 마스크 오차 |
|---|---|---:|---:|
| ASR 대조군 | 해당 없음 | 288/288 | 1 |
| 현재 ORDER 공유 산술 → HPRF 보간 | 1,2 | 192/288 | 7,344,762,654,830,521,702 |
| 현재 ORDER 공유 산술 → HPRF 보간 | 1,3 | 0/288 | 7,377,566,780,412,123,530 |
| 현재 ORDER 공유 산술 → HPRF 보간 | 2,3 | 192/288 | 7,344,762,654,830,521,702 |
| 공유 공간을 q로 맞춘 진단용 변형 | 1,2 | 288/288 | 1 |
| 공유 공간을 q로 맞춘 진단용 변형 | 1,3 | 234/288 | 7,380,213,150,438,885,384 |
| 공유 공간을 q로 맞춘 진단용 변형 | 2,3 | 288/288 | 2 |

원래 개별 마스크의 정수 합이 p를 넘은 좌표는 241개다. ASR 대조군은 이들도 복원했다.
현재 ORDER에서 key를 복원한 다음 HPRF를 계산하는 **ASR 자체**에 아래 AMR의 필드
불일치를 적용해 실패한다고 말하면 안 된다.

AMR 단순 보간에서 실패하는 두 이유는 구분된다:

1. **공간 불일치:** `sum lambda_j*s_j = K + v*ORDER`는 modulo ORDER에서는 K지만,
   modulo q에서는 보통 K가 아니다. 큰 ORDER share를 HPRF에 넣어 보간하는 것으로
   이 차이가 반올림 오차가 되지는 않는다. 이 변형에는 작은 E 보장을 부여하지 않았다.
2. **계수에 의한 오차 증폭:** q 공간으로 맞춰도 보간 계수의 정수 lift가 크면 위험하다.
   `1,2`의 계수는 `(2,-1)`이지만 `1,3`은 `(-36901065752194426921,
   36901065752194426922)`다. 모듈러 역원은 실수의 `1/2`가 아니다.

공간이 맞고 이 정수 lift들을 사용할 때 적용한 보수적 합계 오차는:

```text
E_AMR <= (N + sum_j |lambda_j|)/2
Delta > N + sum_j |lambda_j|
p > 2*(Delta*N*B_z + E_AMR)
```

`1,3`에서는 이 최악 상한을 감당할 최소 Delta조차 현재 p의 용량과 양립하지 않는다.
관측 오차도 p/2 근처에 이르렀다. 일부 성공한 round만 고르거나, 용량을 무시하고
Delta를 올려 성공이라고 보고하지 않는다. `2,3`은 관측상 모두 성공했으나 N=2에서
고정 Delta=6은 위 최악 상한을 충족하지 않았다. 작은 Delta 증가로 인증 가능한 경우와
현재 p에서 불가능한 경우를 JSON 출력에 따로 기록했다.

q는 합성수이므로 이 진단을 “q 유한체의 안전한 Shamir”라고 부르지 않는다.
예를 들어 인덱스 `1,6`은 분모 5가 가역이 아니어서 거부된다. runtime의 ORDER를 q로
한 줄 바꾸는 수정은 하지 않았다. 또한 Aion Algorithm 5의 `2f+1` polynomial 일치
검사, Byzantine share 처리, liveness를 구현하거나 검증한 것이 아니다.

## 7. AMR의 더 앞선 장애물: scalar HPRF 출력 역산

원본 코드와 정확히 대조한 식은 좌표별로 다음과 같다:

```text
a_j = (round+block) * column_sum_j mod q
t_j = a_j*k mod q
h_raw_j = floor((p*t_j + floor(q/2))/q)
```

공개 h는 t를 다음 짧은 구간으로 제한한다:

```text
h*q - floor(q/2) <= p*t < (h+1)*q - floor(q/2)
```

현재 `q/p=5`여서 한 좌표의 가능한 t는 대략 5개다. `gcd(a_j,q)=1`이면
각 후보마다 `k=t*a_j^(-1) mod q`를 계산하고 다음 좌표로 대조할 수 있다.
출력을 mod p로 보냈다면 0은 raw 0 또는 p를 모두 허용해야 하며 감사 코드가 처리한다.
round 등의 영향으로 모든 계수가 비가역인 경우도 있으므로 아무 입력에서나 두 좌표로
복원된다고 일반화하지 않는다.

r=4의 아래 공개 fixture는 모두 **처음 2좌표로 정확히 복원**됐다. 키 범위
`1..100000`을 후보 집합으로 사용하지 않았다.

```text
31337
36901065752194439267
73802131504387619278
```

저자 `hprf.py`를 직접 로드한 출력과도 대조했다. 큰 scalar 키를 선택하는 것만으로
이 구조가 안전해지지 않는다는 반례다. 보안 파라미터를 갖춘 벡터-key BLMR에 대한
공격이나 원 논문의 일반적 LWE 가정을 깨는 결과가 아니다.

추가로 q 공간의 진단용 AMR에서 `H(sum_share_j,r)` 두 개를 역산해 합계 키를
보간했다. 두 round의 합계 키 `187344`, `103407`을 복원했고, 차분은 제거된 공개
fixture 키 `83937`이었다. **이 primitive에서는 키 대신 그 HPRF 출력만 보내도
AMR의 키 비공개성 목적이 달성되지 않는다.**

실제 ORDER share의 경우 이 역산이 직접 주는 것은 `share mod q`이지 2047비트
share 전체가 아니다. q 공유 변형의 합계 키 복원 결과를 현재 Flower wire에서 실행한
공격으로 과장하지 않는다. 위 6절은 그 단순 AMR 변환 자체의 수치 실패도 보여준다.

## 8. 다음 방향과 재현 범위

우선순위는 다음과 같이 조정한다.

1. 원본 scalar artifact는 재현 baseline으로 유지하되 비공개성 확보 후보에서 제외한다.
2. 일회성 공유 + 동적 필터링을 유지하려면, 안전한 key-homomorphic/threshold mask
   primitive와 일치하는 공유 공간·bounded reconstruction을 함께 선택한다.
3. 그 구성의 E·p·정밀도 조건과 다중 round/query 보안을 확인한 뒤 mask-binding ZKP를
   설계하고 비용을 측정한다. 그 다음 Flower 연결 및 MGF 비교 실험을 진행한다.

이는 AMR 계열을 포기한다는 뜻이 아니다.
[LERNA §3.2, Appendix E](https://eprint.iacr.org/2023/1936.pdf)는 재구성 계수의
오차 증폭을 명시적으로 다루며 flat sharing 또는 작은 집단의 분모 제거 변형을 제시한다.
해당 변형에는 인코딩·마스크 평가·보안 분석의 추가 변경이 있다. 본 감사에서 이를
구현한 것은 아니며, 계수만 실수로 나누는 수정과 같지 않다. 따라서 “288좌표 통과면
보안 완료, 실패면 fresh key만 가능”이라는 이분법으로 방향을 결정하지 않는다.

재현 명령(저장소 루트):

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=.cache/flower-deps:.cache/author-asr-deps:.cache/torch-deps:. python3 experiments/audit_split_wire_amr.py --source ../Aion/agent/Aion/HPRF
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=.cache/flower-deps:.cache/author-asr-deps:.cache/torch-deps:. python3 -m pytest -q tests/test_split_wire_amr_audit.py
```

후자의 523개 통과에는 작은 p=101, q=505에서 **505개 scalar 키를 전수 대조하는
파라미터 테스트**가 포함된다. 대규모 프로토콜 시나리오 523개를 검증했다는 뜻이 아니다.
모든 테스트 키·입력은 공개 fixture이며 실제 학습 개인 상태를 읽지 않는다.
ZKP 생성·검증, 새로운 AMR 프로토콜, Flower 연결, 장기 학습, production 보안은
이번 작업의 완료 주장에 포함하지 않는다.
