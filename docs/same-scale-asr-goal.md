# 2026-10-08 현재 목표: 단일 벡터·동일 스케일 MGF와 Aion-ASR

최신 사용자 지시 및 제품 goal: **`mpc는 넣지마`**.
MPC는 도입하지 않는다. 아래는 기존 carry 작업의 배경/검증 기준이며,
이 지시의 반영을 carry 해결이나 Aion-ASR 구현 완료로 간주하지 않는다.

사용자 요청: MGF와 집계 모두 동일한 유효 마스크 `a_r HPRF(k_i,r)`를
사용하는 것을 최종 목표로 한다. 기존 분리 집계+ZKP 계획은 이 목표의
선행 조건으로 사용하지 않는다.

## 목표와 완료 기준

클라이언트가 로컬 업데이트를 양자화하고 하나의 마스킹 벡터를 Flower로
보낸다. 같은 벡터에 MGF를 적용하고 통과한 집합만 BFT①로 확정한다.
초기 일회성 공유를 이용한 ASR로 그 집합의 합계 키를 복원한다. 클라이언트와
동일한 스케일을 사용해 정확한 양자화 업데이트 합을 얻고, 평균을 모델에
반영한 뒤 BFT② 결과를 확정한다.

완료에는 다음 증거가 필요하다.

1. 원본 HPRF와 스케일/전송 반올림을 포함한 정수·유리수 복원 근거.
2. 부호/참여자 수/모델 차원이 바뀌어도 명시된 조건에서 좌표별 정수 합 일치.
3. 기존 ambiguous 반례를 잘못된 성공으로 받아들이지 않는 검사.
4. 실제 학습 범위가 복원 전제에 맞는지 확인하고 Flower 짧은 실행으로 검증.
5. 같은 송신 벡터로 MGF를 검사했다는 증거와 스케일/양자화 변경 영향 보고.

개별 키·평문을 서버에 전달하거나 공개 carry/추가 mask share를 보내는 방법을
해결로 간주하지 않는다. 기존 HPRF, VSS, ASR, Flower 전달을 유지한다.
**MPC는 런타임·통신 경로·외부 backend에 추가하지 않는다.** 기존 VSS/ASR의
share 합산은 유지하며 별도의 비공개 공동 계산 프로토콜을 덧붙이지 않는다.
ZKP/HE, 새 HPRF, clipping, beta 변경을 런타임에 자동으로 도입하지 않는다.
그러한 변경이 필요하면 효과와 변경 범위를 수치 결과와 함께 구체적으로 제시한다.
이는 carry 정확성 작업이며 원본 HPRF의 보안성이나 ASR 누출이 해결됐다는 뜻이 아니다.

사용자 추가 지시: **수식 변경은 허용하되 MGF의 원래 목적인 bound 검증에
영향이 없어야 한다.** 식이나 beta를 문자 그대로 고정하는 요구가 아니다.
후보 수식은 bound가 제한하는 업데이트의 의미, 정상 입력 처리, wire 변조에
대한 복원 증폭 여부를 검증해야 한다. 기존 bound에서 정상 fixture 전원을
탈락시키는 capacity-raised scale이나 대폭 clipping을 해법으로 채택하지 않는다.
MGF 기능을 보존하는 수식 변경의 연구·구현은 허용된 범위이며, 식 변경 자체에
대해 같은 승인을 다시 요청하지 않는다.

추가 명확화: 모든 입력에서 기존 식과 판정이 문자 그대로 일치해야 한다는
뜻은 아니다. 변경된 식에서도 공개 bound가 제한하는 업데이트의 의미와
허용 오차를 명시하고, **검사한 벡터의 bound가 실제 복원된 업데이트에
어떤 상한을 보장하는지** 입증해야 한다. 정상 입력의 복원만 맞거나
정상 fixture의 통과 명단만 같다는 이유로 채택하지 않는다. 마스크에 따른
기존 허용 여유와 양자화 오차를 구분하며, 작은 wire 변조가 그 상한을 넘는
업데이트로 증폭되는 후보는 제외한다.

## 현재 확인된 상태

- 일반 모듈러 FixedPoint 경로는 carry를 이미 처리한다. 독립 감사 101,681개
  좌표와 관련 54개 테스트 통과. 이 결과에는 작은 MGF scale이 포함되지 않는다.
- 현재 단일 벡터 paper-scale 경로는 같은 scale을 쓰지만 quantized lift가
  모호하면 거부한다. 단순 center로 교체하면 실제 학습 합이 범위를 벗어난다.
- 이전 평균 기반 스케일의 FMNIST 4라운드 공개 기록을 재검사했다.
  각 2명 집계에서도 r2~r4는 centered 범위를 벗어난다. 같은 공개 업데이트에
  SUM 기반 스케일을 대입해도 범위를 벗어난다. 새 학습 실행 결과는 아니다.
- MGF 이전에 wire를 modulo로 줄이면 검사 결과가 달라진다.
- 새 공개 수치 도구 `experiments/audit_same_scale_feasibility.py`는 original
  scale, capacity-raised scale, update-bound 제한 후보를 비교한다.
  후보는 기존 런타임에 연결하지 않는다.

## 실행 순서

1. 원본 scale에서 허용 가능한 sum bound와 wire/HPRF 오차를 정확히 계산한다.
2. 같은 scale을 MGF와 집계에 동시에 적용하는 후보를 비교한다. 파라미터로
   해결되는 경우와 업데이트/필터 의미를 바꿔야 하는 경우를 구분한다.
3. 입증된 복원 조건이 실제 workload에 적용될 때만 새 profile로 연결한다.
   조건이 맞지 않으면 clipping/scale 확대/추가 프로토콜 중 필요한 변경을
   명시하며 그 선택을 사용자 승인 없이 논문 재현으로 간주하지 않는다.
4. 연결 후 synthetic → FMNIST 짧은 실행 → 가중 평균 순으로 검증한다.

## 첫 단계 결과

`experiments/audit_same_scale_feasibility.py`와
`tests/test_same_scale_feasibility.py`를 추가했다. 기존 scaled-ring/collision
검사까지 **37 passed (0.45s)**. 런타임/HPRF/메시지 형식은 변경하지 않았다.

공개 fixture: 20명, 8좌표, 각 업데이트 0.01, 이전 공개 크기 0.1,
beta=0.2, MGF bound=0.1, decimals=6, 원본 HPRF round=4.

| 후보 | mask period P | MGF 통과 | 실제 합 | center 결과 |
|---|---:|---:|---:|---:|
| 원래 스케일 | 0.02 | 20/20 | 0.2 | 0 (8좌표 모두 오류) |
| 용량에 맞춰 같은 스케일을 확대 | 약 0.8000004 | 0/20 | 0.2 | 0.2 |
| 원래 스케일, 입력 좌표를 0.00025로 제한 | 0.02 | 별도 학습 검증 전 | 0.005 | 0.005 |

두 번째 후보는 클라이언트와 서버가 동일 scale을 사용하지만 beta가 약
8.000004로 바뀐다. 세 번째 후보는 업데이트의 1/40만 남겼다. 어느 것도
원본 scale 정책과 원래 업데이트를 동시에 보존하는 완성 해법은 아니다.
이 결과는 정렬된 양수 공개 fixture이며 실제 FMNIST 정확도 저하나 모든
학습 분포에 대한 수치가 아니다. 2/20/100명에서도 같은 종류의 조건을 검사했다.

용량 조건에는 `E=ceil((n+1)/2)`와 전송 rounding `n/(2D)`를 포함한다.

```
n*B + (P/p)*E + n/(2D) < P/2
P > (n*B + n/(2D)) / (1/2 - E/p)
```

별도로 총 rounding error `< 1/(2S)`도 검사한다. P를 키우면 집계 용량은
늘지만 HPRF error의 실수 크기도 커지므로 용량 검사 하나만으로 충분하지 않다.

원본 normalized scale에서는 `P=beta*L`이라 p를 늘려도 P가 늘지 않는다.
현재 sum 기반 설정에서 beta=0.2이면 단순 center는 현재 합의 크기가 이전
공개 기준 L의 약 1/10보다 작아야 한다. MGF 통과 여부가 이 조건을 보장하지 않는다.

다음 구현 결정에는 다음 중 허용하는 변경이 명확해야 한다.

- 같은 scale 사용은 유지하되 scale 계산/입력 범위/임계값 정책을 바꿀 것인지.
- 원래 scale과 업데이트를 유지하고 추가 비공개 복원 절차를 허용할 것인지.

후속 사용자 지시로 수식 변경은 허용됐으며 MGF bound 검증을 훼손하는 방법은 제외됐다.
복원에 필요한 추가 비공개 절차는 아직 도입하지 않았으며, 그 필요성 및
범위를 검증한 뒤 구체적으로 제시해야 한다.

현재 집계 합+합계 키 입력만 사용하는 decoder에는 기존 다좌표 반례가
남는다. 두 선택 모두 원본 그대로의 단순 통신 포팅을 넘어가는 변경이며,
구체적인 정확성/비공개성/비용 검증 전에 완성 해법으로 표시하지 않는다.

## 현재 코드의 실제 Flower 확인

[2026-10-08 공식 실행](reproduction/same-scale-current-flower-2026-10-08.md)에서
synthetic은 3-round commit 후 r4 ambiguous로 종료됐고, FMNIST는 4-round
완료 및 selected training replay 8회 모델 오차 0을 확인했다. 초기 공유
80건/추가 mask share 0건이며 sum 기반 scale과 기존 MGF를 사용했다.
같은 코드에 성공과 실패가 모두 있으므로 목표는 미완료다. 단순 단위 변경의
MGF 판정 보존과 복원 용량 불변성, 격자 모호성 진단을 추가해 관련 48개
회귀 검사가 통과했다. MGF 목적을 보존하는 식 변경은 허용된 범위로 계속 검토한다.

## 미세 스케일 변경의 검사

[동일 스케일 jitter 후보](reproduction/same-scale-jitter-bound-2026-10-08.md)는
scale을 약 2.27e-6 비율만큼 줄여 grid phase를 분리했다. 공개 fixture에서
정상 정수 합은 모두 맞고 MGF 명단 변화도 0이었지만, 한 sender의 wire 변화
1.36e-7이 합계 0.06으로 증폭되는 반례가 있었다. 다른 sender가 zero update인
fixture에서 decoded 변화가 한 sender의 MGF bound+mask budget을 초과했다.
따라서 이 후보는 채택하지 않는다. 관련 59개 테스트가 통과했다.

이는 수식 변경 권한이 부족해서 중단한 경우가 아니라 구현 후보를 실제
반례로 배제한 것이다. 다음에는 정상 복원뿐 아니라 masked-bound를 검증한
값과 복원된 update의 관계를 유지할 조건까지 정당화해야 한다.

## 실제 decimal-mask 합을 이용한 수치 기준 구현

[2026-10-08 기준 구현](reproduction/same-scale-mask-sum-reference-2026-10-08.md)은
공개 fixture 키로 실제 개별 HPRF를 스케일링/반올림한 정수 합을 계산했다.
같은 MGF 식과 wire에서 61,706좌표의 정확한 정수 합을 확인했고, 기존 collision을
구분하고 jitter 증폭 wire를 off-grid로 거부했다. 관련 검사는 78 passed다.
서버의 개별 키 조회나 oracle을 런타임 해결책으로 도입하지 않았다.

이 기준 보정을 실제로 제공하려면 기존 합계 키 기반 ASR 평가보다 추가적인
정보/계산이 필요하다. 초기 share를 재사용하는 위원회 MPC를 후보로 제시했지만,
최신 사용자 지시에 따라 **제외**한다. 공개 fixture oracle도 런타임에 넣지 않는다.

또한 정확한 update sum과 masked sum을 같은 관찰자에게 공개하면 mask sum이
역산되고, 실제 fixture에서는 carry까지 추론됐다. 따라서 MPC 내부에서 mask sum을
공개하지 않는 것만으로 carry 누출이 해결됐다고 주장하지 않는다. 추가 메시지
비공개성과 최종 출력에서 추론되는 정보의 정책을 구분해서 검토해야 한다.
기존 carry 목표의 완료를 주장하지 않는다. MPC 확장 승인 요청은 철회한다.

## 실제 Flower 결과의 정보 흐름 추가 확인

[실제 수신 메시지 감사](reproduction/source-output-information-2026-10-08.md)는
개인 키/share/학습 데이터 없이 기존 공식 FMNIST 결과를 검사했다. r1의 signed
VECTOR와 확정 평균으로 61,706좌표의 decimal-mask sum을 역산하고 확정 projection
norm과 일치를 확인했다. r2~r4는 평균에서 정수 합을 식별했지만 packet 파일이
없어 mask sum 검증은 증거 부족으로 구분했다. 관련 검사 88개 통과.

이는 새 secure 복원 구현이 아니다. 공개 평균과 수신 vector가 드러내는 정보의
검토 결과는 유지하지만 MPC 계산 계층은 추가하지 않는다. 이미 확인한 반례를
무시하거나 private 키 조회로 우회하지 않으며, 기존 런타임은 모호한 복원을
거부하는 현재 동작을 유지한다.
